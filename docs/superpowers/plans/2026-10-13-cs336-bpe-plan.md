# CS336 A1 BPE Pair-Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Determine whether exact local pair updates can speed up A1 BPE without unsafe memory growth, and adopt a candidate only if it passes the agreed gates.

**Architecture:** Keep original/cs336_basics/bpe.py as the reference and the current heap-based implementation as fallback. Compare a low-memory one-pass update with a compact occurrence-index candidate behind an explicit strategy flag; change the default only after exact-output, speed, and memory gates pass.

**Tech Stack:** Python 3.12, regex, NumPy, psutil, pytest.

**Spec:** docs/superpowers/specs/2026-10-13-cs336-bpe-ddp-design.md

## Global Constraints

- Preserve original/ and do not overwrite its Python source.
- Merges and vocab bytes must exactly match the original implementation for the same input.
- Pair selection remains max(count, pair bytes tuple), preserving the existing tie-break.
- Keep tracemalloc disabled during performance and RSS measurements.
- Increase samples in order: 64 MiB, 256 MiB, then 512 MiB; do not start full OWT before the memory gate passes.
- Accept a candidate only with exact equality, at least 1.2x median total speed at 256 MiB, peak RSS at most 1.5x current, and projected full-run peak below 60% of headroom, where headroom is min(memory.max - memory.current, MemAvailable).
- The remote project has no Git metadata; preserve results in the remote project and publish through the authorized GitHub path only after verifying target repository and write access.

## Review Focus

- Overlapping matches such as a a a merge left-to-right once: test_left_to_right_non_overlapping_merge in Task 1.
- Equal-frequency pair ordering matches the byte-tuple tie-break: test_tie_breaks_match_reference in Task 1.
- Special-token boundaries remain intact: test_special_token_boundaries_match_reference in Task 1.
- Empty and one-token sequences cause no invalid index access: test_empty_and_single_token_inputs in Task 1.
- Larger worker counts stay within the RSS gate: test_benchmark_reports_process_tree_memory in Task 4.
