# A1 BPE 速度优化与训练参数审查

更新：2026-10-13

## 修改内容

- original/ 保存修改前 cs336_basics/、scripts/、tests/ 下全部 Python 文件；original/SHA256SUMS 可用于校验备份。
- cs336_basics/bpe.py 用最大堆选择最高频 pair，并保持原实现的精确优先级：先按频次，再按 pair 字节序取最大值。过期堆项惰性丢弃；堆超过当前 pair 数的两倍（至少 64 项）时重建。
- 合并时只访问包含目标 pair 的词。按词计算合并前后的 pair 频次差，聚合后一次性更新全局计数；不再先扫描每个受影响词构建 set(iter_pairs(...))，也不再逐词删除、重加全部 pair。
- scripts/run_bpe_experiment.py 默认不启动 tracemalloc。需要峰值内存时显式传 --trace-memory；数据路径、词表大小和输出前缀也可通过命令行覆盖。
- scripts/tokenize_corpus.py 可将文本流式转换为 uint16 的 .npy token IDs，不需要把整份语料和 Python 整数列表同时放进内存。
- cs336_basics/train.py 支持 torchrun/DDP，batch_size 表示每个 rank 的 batch。CUDA 训练使用 pinned-memory batch 和独立 CUDA stream 预取下一批数据。
- scripts/run_tinystories_training_pipeline.py 会下载 TinyStories、训练 10k BPE、编码 train/valid 并启动 4 卡训练；训练和数据产物写入 outputs/。
- 按要求删除项目根目录的 AGENTS.md。

## 正确性和耗时

在远端同一 Python 环境下，以 OWT 训练集前 64 MiB 为输入、vocab_size=1024、不启用内存追踪，分别运行原版与优化版：

| 版本 | 用时 |
|---|---:|
| 原版 | 16.902 秒 |
| 优化版 | 15.287 秒 |

优化版约快 1.11 倍（10.6%）。两次的 vocab 和 merges 完全相同（1024 个词表项、767 次 merge）。这是单次、有限样本对照；它不等于完整 OWT、32k 词表的耗时预测。完整 OWT 的 BPE 尚未运行。

课程测试与新增测试共 55 项通过、1 项 xpassed，包含课程要求的 500 词表速度测试、参考 merge/vocab 等价性、special-token 样例、堆 tie-break/过期项清理、120 次随机 merge 后 pair 计数和索引对照，以及 token ID 流式写入和 uint16 边界检查。原版备份 SHA256 校验通过。

同一 64 MiB 样本、1024 词表的 profile 显示：预切分和计数 4.408 秒，pair 选择 0.019 秒，merge 更新 9.693 秒。预切分/计数已由 4 个进程并行；逐轮 merge 目前单进程。继续利用多核有空间，但需要让 worker 持有分片状态并避免每轮反复序列化大量词数据，不能简单地每轮新开进程。本次没有加入这类复杂并行实现。

## 词表和训练参数

- OWT 的 A1 BPE 目标词表为 32,000；32k 是 tokenizer/model 的 vocab_size，不是训练步数。课程 A1 的 OWT 配置使用 32k 词表。[课程 A1 leaderboard](https://github.com/stanford-cs336/assignment1-basics-leaderboard)
- 当前 scripts/run_bpe_experiment.py 默认 vocab_size=32000。scripts/run_tinystories_train.py 是 TinyStories 实验，固定使用 10,000 词表；这不应拿来配置 OWT。
- A1 的 TinyStories 训练基准处理约 327,680,000 tokens，而不是固定步数。按四卡 DDP、每卡 batch 16、context 256（全局 batch 64）计算，默认 20,000 步正好达到该 token 预算；单卡 batch 16 跑 20,000 步仅处理 81,920,000 tokens。
- 训练默认 num_steps=20,000、cosine_cycle_iters=20,000、eval_every=1,000、save_every=5,000；训练结束仍保存最终 checkpoint。DDP 已通过物理 GPU 4–7 的四进程 smoke test，验证了前向/反向、验证聚合和主 rank checkpoint 保存。正式长训仍待 BPE 和 tokenization 完成。

## 多卡检查

train.py 根据 torchrun 环境变量初始化 NCCL/DDP，每个 rank 独立抽样并计算梯度，DDP 对梯度求平均；只有 rank 0 写日志和 checkpoint。CUDA batcher 将下一批搬到 pinned memory，并在独立 CUDA stream 上预取，以与当前训练计算重叠。用户选择的物理 GPU 4–7 已通过两步 smoke test。
