# A1 BPE 速度优化与 OWT 训练

更新：2026-10-14

## 实现

- `original/` 保留修改前 `cs336_basics/`、`scripts/`、`tests/` 下全部 Python 文件；`original/SHA256SUMS` 可用于校验备份。
- `cs336_basics/bpe.py` 用最大堆选择最高频 pair，并保持原实现的精确优先级：先按频次，再按 pair 字节序取最大值。过期堆项惰性丢弃；堆超过当前 pair 数的两倍（至少 64 项）时重建。
- 合并时只访问包含目标 pair 的词。按词计算合并前后的 pair 频次差，聚合后一次性更新全局计数；避免逐轮扫描完整 pair 计数。
- `scripts/run_bpe_experiment.py` 默认不启动 `tracemalloc`；需要峰值内存时显式传 `--trace-memory`。
- `scripts/tokenize_corpus.py` 流式编码语料为 `uint16` `.npy` token IDs，不会把整份语料和 Python 整数列表同时放进内存；支持有界任务队列的多进程编码，按输入顺序写出结果。
- `cs336_basics/train.py` 支持 `torchrun`/DDP，`batch_size` 表示每个 rank 的 batch；CUDA 训练以 pinned-memory batch 和独立 CUDA stream 预取数据。
- `scripts/run_owt_training_pipeline.py` 复用已经完成的 OWT 32k BPE，分别编码 OWT train/valid，再用 GPU 4–7 启动四卡训练。流程不下载其他语料，也不会重新运行 BPE。
- `cs336_basics/train.py` 和 OWT 流水线支持 `--resume-from`，从 checkpoint 恢复模型和优化器状态，并从保存 step 的下一步继续原有 20k cosine 计划。续训指标和日志分别写入 `outputs/logs/owt_32k_resume.csv` 与 `outputs/logs/owt_4gpu_train_resume.log`，避免和未保存到 checkpoint 的旧进度混在一起。
- 项目根目录的 `AGENTS.md` 按此前要求移除。

## BPE 正确性与耗时

在远端同一 Python 环境下，以 OWT 训练集前 64 MiB 为输入、`vocab_size=1024`、不启用内存追踪，分别运行原版与优化版：

| 版本 | 用时 |
|---|---:|
| 原版 | 16.902 秒 |
| 优化版 | 15.287 秒 |

优化版约快 1.11 倍（10.6%）。两次的 vocab 和 merges 完全相同（1024 个词表项、767 次 merge）。这是单次有限样本对照。

完整 OWT（11,920,511,059 字节）、`vocab_size=32,000` 的优化版实测耗时 1,285.23 秒（约 21 分 25 秒），输出 32,000 个词表项和 31,743 次 merge；其中预切分/计数 734.94 秒、pair 选择 3.50 秒、merge 更新 514.89 秒。未启用 `tracemalloc`。产物为 `outputs/owt_bpe_32k.vocab.pkl` 和 `outputs/owt_bpe_32k.merges.pkl`。

优化版已用参考实现做 vocab/merges 等价性检查，并覆盖堆 tie-break、过期项清理及 120 次随机 merge 的 pair 计数和索引核对。预切分和计数阶段使用 4 个进程并行；逐轮 merge 仍是单进程，继续并行需要让 worker 长期持有分片状态并避免反复序列化大词表状态。

OWT tokenizer 在远端以训练集前 8 MiB 对照：单 worker 14.42 秒，16 workers 2.15 秒，约快 6.69 倍；两种方式得到完全相同的 1,910,048 个 token ID。完整流水线使用 16 个 tokenizer worker，并将待处理文本块限制在有界队列中。

## OWT 训练参数

- BPE 词表：32,000。
- GPU：物理 GPU 4、5、6、7，DDP 四进程。
- 每卡 batch：16；全局 batch：64；context length：256。
- 训练步数：20,000；按 `20,000 × 64 × 256` 计算，处理 327,680,000 个 token。
- 模型：4 层、`d_model=512`、16 heads、`d_ff=1344`。
- 学习率：`3e-4` 到 `3e-5`，warmup 100 步，cosine cycle 20,000 步。
- 验证间隔：1,000 步；每次 10 个 batch。checkpoint 间隔：5,000 步，并在训练结束保存最终 checkpoint。
- checkpoint、指标和日志分别写入 `outputs/checkpoints/`、`outputs/logs/`；状态写入 `outputs/owt_a1_train.status.json`。

### 断点续训

如果训练被中断，可运行：

```bash
python scripts/run_owt_training_pipeline.py \
  --physical-gpus 4,5,6,7 \
  --resume-from outputs/checkpoints/owt_32k_latest.pt
```

checkpoint 同时保存模型、AdamW 状态和 step 编号。恢复后会继续剩余训练步数，并沿用以 20,000 步为周期的学习率计划。此次续训从 step 10,000 的 checkpoint 恢复；旧日志里 10,000 之后、checkpoint 保存前的进度不在 checkpoint 中，会从保存状态重新计算。

### Prompt 续写

`scripts/run_generate.py` 默认加载 OWT 32k tokenizer 和最终 checkpoint，模型结构默认与训练配置一致。运行时只需提供 prompt：

```bash
python scripts/run_generate.py --prompt "Once upon a time"
```

默认最多生成 100 个新 token，temperature 为 0.8、top-p 为 0.9。默认优先使用可见 GPU 4；设备少于 5 张时使用默认 CUDA 设备，无 CUDA 时使用 CPU。

DDP 已用物理 GPU 4–7 完成两步 smoke test，验证前向/反向、验证 loss 聚合和 rank 0 checkpoint 保存。完整 OWT 训练由新流水线启动后，以状态文件和日志记录实际进度。

上一轮完整测试集为 65 passed、1 xpassed；1 项 xpassed 是原课程测试中已满足预期的标记。生成参数本轮新增的 3 项测试全部通过，并实际用仅带 `--prompt` 的命令完成了一次 OWT 续写。
